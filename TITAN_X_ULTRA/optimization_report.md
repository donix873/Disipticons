# TITAN X ULTRA — отчёт по оптимизации

Дата анализа: 20 ноября 2026 г.

## Область проверки

Отчёт задаёт ограничения для новой сборки `TITAN_X_ULTRA` под macOS и Blender 2.82.7. Итоговый файл собран и измерен в Blender 4.3.2. Эти показатели подтверждают лёгкость сцены, но **не доказывают** совместимость с Blender 2.82.7: целевая версия Blender на macOS фактически не запускалась.

### Оценка 37 не применённых модификаторов

Число 37 превышает заданный жёсткий ориентир 20. Формально это предупреждение, а не PASS. При этом сцена содержит всего 63 объекта и 1 489 полигонов, поэтому вычислительная нагрузка модификаторов для современного Mac ожидается небольшой: базовая геометрия крайне лёгкая, а размер файла составляет около 1,1 MiB.

Такое количество можно принять для редактируемой демонстрационной версии, если все модификаторы совместимы с Blender 2.82.7 и воспроизведение кадров 1–90 остаётся плавным на целевом Mac. До этого запуска условие считается **приемлемым с оговоркой**, а не окончательно подтверждённым. Для релизной копии рекомендуется применить модификаторы на полностью статичных деталях, сохранив редактируемый исходник отдельно; цель — не более 20, без применения модификаторов на подвижных или параметрически важных элементах.

| Ресурс | Цель | Жёсткий предел | Причина |

| Материалы | 7–8 | 10 | Один общий набор без дубликатов |

| Источники света | 3 | 5 | Key/fill/rim достаточно для демонстрации |
| Камеры | 3 | 5 | Главный, верхний и технический ракурс |
| Actions | 1 общая или до 6 | 10 | Не создавать action для каждой неподвижной детали |

Функциональные детали нельзя объединять или удалять только ради достижения численного лимита. Подвижные рычаги, шарниры, ограничители и съёмные панели должны оставаться отдельными объектами.

## Совместимость Python API с Blender 2.82.7

Обязательные ограничения:

- Использовать `scene.render.engine = 'BLENDER_EEVEE'`. Значение `BLENDER_EEVEE_NEXT` из текущего генератора относится к новым версиям и в 2.82.7 не поддерживается.
- Не использовать Geometry Nodes, Asset Browser API, `bpy.context.temp_override`, новые node types и другие возможности, появившиеся после ветки 2.82.
- Для STL в 2.82.7 использовать доступный там оператор `bpy.ops.export_mesh.stl(...)` при включённом аддоне STL. Вызов `bpy.ops.wm.stl_export(...)` из Blender 4.x несовместим.
- Не полагаться на имена новых входов Principled BSDF. Использовать входы, существующие в 2.82.7: `Base Color`, `Metallic`, `Roughness`, `Emission` и `Emission Strength` только после проверки наличия входа.
- Не использовать Eevee Next, Cryptomatte-настройки новых версий, новые параметры shadow maps или новые enum-значения color management без проверки `hasattr`/наличия ключа.
- Коллекции, `bpy.data.collections`, keyframes, parenting, Bevel/Solidify и стандартные mesh primitives допустимы в 2.82.7.
- Экспорт GLB считать дополнительным: аддон glTF может быть отключён. Ошибка экспорта не должна ломать создание `.blend`.

Рекомендуемый шаблон проверки версии:

```python
if bpy.app.version < (2, 82, 0):
    raise RuntimeError("Required Blender 2.82 or newer")
```

Не следует запрещать запуск в новых версиях, но для различающихся операторов нужен отдельный совместимый путь.

## Геометрия и модификаторы

- Применять Bevel к простым статичным деталям после построения, если дальнейшее изменение радиуса не требуется.
- Для редактируемых внешних панелей оставлять максимум один Bevel и один Weighted Normal; сегменты Bevel — 1–2 в рабочей сцене и не более 3 для крупного плана.
- Не применять Subdivision Surface к корпусу, раме, клину, колёсам и техническим креплениям. Округление должно создаваться фасками.
- Не оставлять Boolean-цепочки в итоговой сцене. После проверки результата применить Boolean и удалить операнды либо скрыть их в явно названной служебной коллекции.
- Не использовать Array для нескольких единичных болтов, если копии не дают заметной экономии; мелкий крепёж лучше ограничить визуально важными точками.
- Для четырёх одинаковых колёс использовать связанные mesh data, сохраняя отдельные объекты и трансформации.
- Цилиндры: 20–24 вершины для колёс и крупных шарниров; 12–16 для болтов, втулок и осей.
- Не моделировать резьбу, внутренности закрытых моторов, платы по отдельным компонентам и невидимый крепёж.

Тяжёлые или нежелательные элементы: Subdivision Surface, Remesh, Skin, повторяющиеся Boolean, высокосегментные Bevel, частицы, объёмный свет, motion blur и глубина резкости во время работы во viewport.

## Материалы и текстуры

- Использовать единый словарь материалов; не создавать материалы вида `gunmetal.001` для каждого объекта.
- Базовый набор: gunmetal, matte black, brushed steel, rubber, dark panel, safety red и red indicator.
- «Шлифованный металл» имитировать умеренной roughness, а не 4K-текстурой.
- Красное свечение оставить только индикаторам. Большие emissive-панели и bloom не использовать.
- До сохранения удалить материалы с `users == 0`, а также проверить отсутствующие изображения и внешние пути.

## Облегчённая конфигурация сцены

### Viewport

- Работать в `Solid` shading; Material Preview включать только для проверки материалов.
- Отключить cavity/shadows/specular во время тяжёлого редактирования на слабом Mac.
- Для коллекций `LIGHTS`, `CAMERAS`, `PRESENTATION` и технических аннотаций использовать отдельные переключатели видимости.
- Установить `Simplify` для рабочих сессий: subdivision 0, texture limit 1024, без motion blur.
- Скрывать внутреннюю электронику при правке внешнего корпуса, но не удалять её.

### Предпросмотр Eevee

- Разрешение: 960×540 или 1280×720, 50% scale для быстрых проб.
- Eevee TAA render samples: 32; viewport samples: 16.
- Ambient Occlusion: включить для финального предпросмотра, выключать при геометрической правке.
- Screen Space Reflections, volumetrics, soft shadows и bloom — выключены по умолчанию; включать только при доказанной визуальной необходимости.
- Прозрачность корпуса не использовать. Для внутреннего ракурса скрывать съёмную крышку, чтобы детали не просвечивали через закрытую геометрию.

### Финальный демонстрационный рендер

- 1280×720, Eevee, 64 samples; 1920×1080 использовать только для итоговых кадров.
- PNG, RGBA только если действительно нужен прозрачный фон; иначе RGB.
- Анимацию сначала выводить в последовательность PNG, затем собирать видео. Это позволяет продолжить после сбоя.

## Очистка перед сохранением

1. Сохранить отдельную резервную копию до очистки.
2. Удалить только явно временные объекты и тестовые камеры.
3. Проверить `bpy.data.meshes`, `materials`, `images`, `actions` с `users == 0`.
4. Удалять orphan data программно по типам либо через Outliner; не полагаться на оператор, которому нужен неверный UI context в background mode.
5. Выполнить `File > External Data > Report Missing Files`.
6. При наличии нужных внешних изображений выполнить `Pack Resources`; в предпочтительной процедурной конфигурации внешних ресурсов быть не должно.
7. Сохранить, закрыть Blender и повторно открыть файл в Blender 2.82.7.

## Приёмочные проверки новой сборки

После появления `TITAN_X_ULTRA.blend` уже измерены размер файла, количество объектов, mesh data, вершины, полигоны, материалы, камеры, источники света и оставшиеся модификаторы. На целевом Mac всё ещё необходимо измерить:

- точную версию Blender, в которой файл открыт;
- изображения и actions, если они не внесены в итоговый `build_report.json`;
- время открытия файла и время рендера одного кадра на целевом Mac;
- среднюю отзывчивость viewport при воспроизведении анимации;
- наличие дубликатов материалов и orphan data;
- успешное открытие, запуск скриптов и воспроизведение кадров 1–90 именно в Blender 2.82.7.
